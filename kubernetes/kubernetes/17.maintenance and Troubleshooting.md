# Maintenance and Troubleshooting

## Application logs

The stdout and stderr container logs are sent to a log file managed by kubelet in `/var/log/containers`.

They are accessible by `kubectl logs` command.

If there are two containers inside of one Pod, you must add a `-c` and specify the container to access.


How does it work:
When you run kubectl logs, kubelet retrieves directly from the log file on the node: only the latest log content are provided, not the log entries that have already been archived (rotated).

## System logs

For non-container components (e.g., the kubelet and the container runtime), logs will be written to journald if systemd is available (/var/log with the file extension .log otherwise)


## Application rollouts

Every time Pods are changed within a Deployment, a new revision is created.

**History**: We can see the rollout history, example 
`kubectl rollout history deploy _deploy_name_`

**Add comment to version**: you can add a note to the current version: 
`kubectl annotate deploy _deploy_name_ kubernetes.io/change-cause="This is a web server deployment"`

**Rollback**: 
`kubectl rollout undo deploy _deploy_name_`

or:
`kubectl rollout undo deploy _deploy_name_ --to-revision=1`


**Check status:**
`k rollout status deploy nginx --revision 3`
or just 
`k rollout status deploy nginx`

**Check status:**
`k rollout status deploy nginx --revision 3`

**Pause and resume**:
`k rollout pause/resume deploy apache`


## Remove a node from the cluster

The following procedure guarantee no application downtime. 

**1 - cordon = disable scheduling**

`kubectl cordon _node_name_`

The node is make unschedulable.
The status of the node pass from Ready to Ready,SchedulingDisablled.


**2 - drain = remove all pods from the node**
`kubectl drain _node_name_ --ignore-daemonsets`

The `--force` option will cause the deletion of pods not controlled by controllers (like deployments, etc)


**3 - remove = remove the node form the cluster**
`kubectl delete node  _node_name_`


## Add a node from the cluster

Adding a node to an existing kubeadm cluster is simplified by enabling bootstrap token authentication in the Kubernetes API: you can see it in the kube-apiserver manifest.


Bootstrap tokens are essentially bearer tokens used when creating new clusters or joining new nodes to an existing cluster. These tokens were primarily built for kubeadm but can also be used in other scenarios.


**Create a token**

On the main node:
`kubeadm token create --print-join-command`

output example:
kubeadm join 54.73.214.175:6443 --token gu230f.d8r5iaybubwiovh3 --discovery-token-ca-cert-hash sha256:6xxx.... 

This output can be then used on the target node you want to add to the cluster

## DNS

### Change CIDR

The CIDR is controlled by the **API server** and its configuration in /etc/kubernetes/manifests. The option is `--service-cluster-ip-range`.
When you need to change the ip addresses for DNS, other edits are needed:
- the **kube-dns service** have to be provided a new ip
- the configuration for **kubelet**: /var/lib/kubelet/config.yaml -> ClusterDNS
- the **ConfigMap kubelet-config** -> ClusterDNS
#### How to change CIDR used by DNS
##### 1 - change api-server conf: 
   /etc/kubernetes/manifests (--service-cluster-ip-range)
   example:  10.96.0.0/16 ->  100.96.0.0/16
##### 2 - change dns service ip
kubectl -n kube-system edit svc kube-dns
```yaml
spec:
  clusterIP: 10.96.0.10 -> 100.96.0.10
  clusterIPs:
  - 10.96.0.10 -> 100.96.0.10
```

Note: on edit of this service, an error will be prompted because only certain types of parameters can be changed for Kubernetes objects that are in a running state.
so, to edit use the command kubectl replace -f .. **--force**

##### 3 - change kubelet config
edit the file /var/lib/kubelet/config.yaml
ex:
```yaml
clusterDNS:
- 10.96.0.10 -> 100.96.0.10
```

##### 4 - change the ConfigMap kubelet-config
kubectl -n kube-system edit cm kubelet-config

##### 5 - reload kubelet
systemctl daemon-reload
systemctl restart kubelet

##### 6 - test it
- `kubectl run netshoot --image=nicolaka/netshoot --command sleep --command "3600"`
- check the dns, the docker should have the good dns: cat /etc/resolv.conf -> nameserver 100.96.0.10
- nslookup example.com should work
