# Vanilla kubernetes





## kubeadm init

### phases

- preflight: check condictions
- certs: a self signed K8s CA is generated, related certificate are created for apiserver, etcd, proxy
- kubeconfig generated
- kubelet-start
- control-plane set up: static Pod a manifest are created and started for apiserver, control manager and scheduler
- etcd: static Pod manifest are created and started for etcd
- upload configs: ConfigMap are created for configurations
- updaload certs: upload all certificates to /etc/kubernets/pki
- mark the node as control plane
- bootstrap token
- finalise kubelets setting


### kubeamn init: some inputs

- **--apiserver-advertise-address**: IP address on which the API server is listening
- **--config**: name of a configuration file (which is used for additional configuration)
- **--dry-run**: to perform a dry-run before actually installing for real
- **--pod-network-cidr**: set the CIDR for the Pod network
- **--service-cidr**": set the service network address


### Network add ons

After the k8s installation, you need to install a network plug-in. 
Examples are:
- **calico**: the most common network with all the relevant feature
- **flannel**: don't support network policy
- **multus**: a plugin that can work with multiple network plugin. default in Openshift
- **weave**: common plug-in that support the most import features

## Important files and directories

**/var/lib/kubelet/config.yaml**:
This configuration is just for the kubelet, and will include the authentication for the kubelet, the health Endpoints, the cluster DNS.


**/etc/kubernetes/manifests**:
Static manifests deployed on the cluster. They are:
- etcd.yaml
- kube-controller-manager.yaml
- kube-apiserver.yaml
- kube-scheduler.yaml




## kubernet infrastructure

**Control plane - core elements:**

| element            | run as                 | description                                                           |
| ------------------ | ---------------------- | --------------------------------------------------------------------- |
| controller manager | run as pod (daemonset) | control loop responsible to matching the current to the desired state |
| api server         | run as pod (daemonset) | it exposes API, it's the entrypoint for all communication             |
| scheduler          | pod                    | (pod): the component that selects the notes on which the pods run     |
| etcd datastore     | pod                    | stores all the Kubernetes configuration data                          |


**Control plane - plugin:**
- CoreDNS -  (pod)

**On all nodes:**

| element           | run as               | description                                                                                                                                                 |
| ----------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| kubelet           | run as linux service | ensure all pods are run and take some corrective actions; if the kubelet can’t make the container run, it will report the status to the API server (events) |
| container runtime | run as linux service |                                                                                                                                                             |
| kube-proxy        | DaemonSet            | communication mechanism                                                                                                                                     |


if the kubelet is not running, your node status will show as NotReady.

## Troubleshooting

### Troubleshooting kubelet

**list services:**
```bash
sudo systemctl list-unit-files --type service --all
```
- if it's stopped: systemctl start kubelet
- if not enabled at boot: systemctl enable kubelet

**simply check its status:**
```bash
systemctl status kubelet
```

**Journald** (Linux system service) is used to collect logs.
**journalctl** is a CLI for viewing logs on a Linux system collected by systemd.

**Check logs for kubelet and containerd:**
```
sudo journalctl -u kubelet
sudo journalctl -u containerd as a reference.
```

You can check the /var/log/pods directory for Pod logs.


### info from the cluster
```bash
kubectl cluster-info
kubectl cluster-info dump
kubectl cluster-info dump --output-directory=tmp
```

### Kubernetes version upgrade

if you used kubeadm to install the cluster, you can update it with the same tool.

After you update packages:
```bash
apt-mark unhold kubelet kubeadm kubectl
apt update && apt upgrade
```

show the update that kubeadm can do
```bash
kubeadm upgrade plan

```

then for example, as suggested by the precedent command
```bash
kubeadm upgrade apply v1.29.2

```

## Working with ETCD

ETCD is the distributed database that store the k8s configuration.

### Backup and restore
you can use the tool etcd-ctl.

Start by checkeing the configuration of the etcd manifest (/etc/kubernetes/manifests)

#### install it
```bash
# install
apt update; apt install -y etcd-client

# set the api version to 3
export ETCDCTL_API=3

```


#### backup db
```bash

# don't forget (as I usually do) to set the api version to 3 
export ETCDCTL_API=3


# save snapshot to file snapshotdb
etcdctl snapshot save snapshot.db \
--cacert /etc/kubernetes/pki/etcd/ca.crt \
--cert /etc/kubernetes/pki/etcd/server.crt \
--key /etc/kubernetes/pki/etcd/server.key

# check it
etcdctl snapshot status snapshotdb



```

#### restore db

this can be made in 2 phases:

- prepare a directory with the restored snapshot
```bash
etcdctl snapshot restore snapshot.db --data-dir /var/lib/etcd-restore
```


edit the k8s manifest to use this directory to use the new directory:

```bash
cd /etc/kubernetes/manifests

```
